# 用浏览器看板(任何设备开浏览器即看)

> 不用装 App、不用越狱:任何能上网、能开浏览器的设备(电脑 / 平板 / Kindle 自带浏览器)
> 打开一个网址,就看到**实时自动刷新**的看板。本文如实写清各设备能做到什么、做不到什么。

## 一句话

- **电脑 / 平板浏览器** → 打开 `/app?token=…` → 实时看板,点 **⛶** 一键全屏(隐藏地址栏/标签栏),点 **⚙** 回设置页。
- **Kindle 自带浏览器(古董 WebKit)** → 打开 `/web-simple?token=…` → 静态整图 + 自动重载的降级页。

地址和令牌从**设置页**(`/setup`)底部「📱 安卓 App 版」那一栏直接拿:
有「🖥️ 在浏览器全屏看板」按钮(点开就是 `/app`)、可复制的链接、以及 `/web-simple` 降级页提示。

---

## 1. 现代浏览器(电脑 / 平板):`/app`

`/app` 本身就是一个**纯网页活看板**:JS 轮询拉数据、自动轮播翻页、自动缩放铺满屏幕。
在电脑/平板的 Chrome / Edge / Safari 里直接打开就能用。本次新增两个浮层按钮(右下角):

| 按钮 | 作用 | 说明 |
|---|---|---|
| **⛶ 全屏** | 进/退浏览器全屏 | 用 **Fullscreen API**,把地址栏/标签栏全隐掉,只剩干净看板;再点退出。**只能由你点击触发**(浏览器安全限制,不能自动进全屏)。进全屏后按钮自动淡到角落,不挡看板,鼠标移上去恢复。 |
| **⚙ 设置** | 跳设置页 | 跳 `/setup?token=…`,沿用当前令牌、不用重输。 |

> 这两个按钮**只在普通浏览器里出现**;安卓 App 壳内(原生已全屏常亮)不显示,避免壁挂误触。

> **全屏后画面怎么铺**:看板是固定 800×600(4:3)版面,全屏时**自动缩放铺满屏幕**——高度方向等比放大填满,宽度方向再轻微拉伸一点,尽量少留白。屏幕越接近 4:3 画面越规整;宽屏(16:9 显示器)上画面会比 Kindle 上略宽一点点(横向轻度拉伸,日常基本看不出来),两侧仍留约 5% 用看板背景色填充(不是黑边)。**平板(iPad 4:3、多数安卓 16:10)几乎看不出差别。** 这是「尽量铺满」与「完全不变形」之间的折中——想一点都不变形就得多留白,我们选了少留白。

### 关于「不息屏」—— 诚实说明 ⚠️

「网页自己保持屏幕常亮」是这件事里**最难、最容易被夸大**的一块:

- 标准做法是 **Screen Wake Lock API**,但它**只在「安全上下文」(HTTPS 或 localhost)可用**。
- 本看板默认是**局域网 HTTP**(`http://192.168.x.x:端口`),**绝大多数浏览器在 HTTP 下根本拿不到 Wake Lock**。
- 所以页面会**尝试**申请常亮,**拿不到就静默放弃、不报错**——但请**别指望「打开网页就永不息屏」**。

**想真的让网页保持常亮,二选一:**

1. **给看板上 HTTPS**(自签证书会有浏览器警告,或用反代 / 局域网证书)→ 现代浏览器的 Wake Lock 就能用、屏幕常亮。**这是唯一靠谱的「网页保持常亮」方案**,但要你额外搭 HTTPS。
2. **直接在设备上设「永不息屏」**(电脑电源设置 / 平板显示设置)→ 最省事最可靠,**壁挂场景建议就这么干**,网页这层不用管。

> **平板(安卓)其实最佳解是装我们的 App** —— 原生 `FLAG_KEEP_SCREEN_ON` 常亮,100% 可靠,
> 不用跟浏览器较劲。见 [`android-app.md`](android-app.md)。

## 2. Kindle 自带浏览器:`/web-simple` 降级页

Kindle 的自带浏览器是古董 WebKit,`/app` 那套现代 JS(fetch / Fullscreen / Wake Lock / 现代 CSS)
八成跑不动。给它一个**最朴素的降级页** `/web-simple?token=…`:

- 服务端直接吐**静态 HTML**,里面就嵌一张 `/kindle/frame.png`(当前看板整图)。
- 页头 `<meta http-equiv="refresh">` 按 `page_interval` 整页定时重载,跟上看板翻页。
- **没有 JS**,古董浏览器也能显示 + 刷新。
- 全屏 / 不息屏对 Kindle 自带浏览器**别指望**(它做不到)。Kindle 真要做常亮壁挂看板,
  **越狱安装看板端**那条路才是正解(见 [`install.md`](install.md)),不是靠浏览器。

## 3. 各设备能做到什么(真实对照表)

| 设备 / 浏览器 | 看板显示 + 自刷新 | 全屏隐 chrome | 网页保持不息屏 |
|---|---|---|---|
| 电脑 Chrome/Edge/Safari | ✅ `/app` | ✅ ⛶ Fullscreen API | ⚠️ 仅 HTTPS;否则靠系统电源设置 |
| 平板浏览器 | ✅ `/app` | ✅ ⛶ | ⚠️ 同上;**更建议直接装 App(原生常亮)** |
| Kindle 自带浏览器 | ⚠️ 古董,用降级页 `/web-simple`(静态 + meta refresh) | ❌ 多半不支持 | ❌ 浏览器做不到(常亮走越狱安装) |

---

## 4. 鉴权与红线

- `/app`、`/web-simple` 都经**访问令牌**(看板数据,沿用现有鉴权)。链接里带 `?token=…`。
- 内嵌的 `/kindle/frame.png` 本就在豁免名单(给 Kindle 拉图),降级页直接复用、不另渲染。
- **纯展示**:浏览器看板这层不引入任何会改设备状态的东西(改设备走 App 的动作接口,另有鉴权)。
- **不夸大能力**:不息屏在 HTTP 下做不到——这点在 UI 和本文里都如实写,别让用户以为打开网页就永不息屏。
